## Problem Statement

Dispatchers see late deliveries in dashboards but must leave the dashboard to act: reassigning stops, approving exceptions, and logging why happen in email, chat, and spreadsheets. Nothing is audited, per-user state does not exist, and the reasons behind decisions never reach the lakehouse, so routing models never learn from them. Result: missed SLAs, expedite and fuel cost, and no evidence in carrier disputes. (Dollar baseline is a workshop-narrative placeholder.)

## Purpose of this repo

Workshop collateral for a Databricks Apps + Lakebase session. One app, built two ways:

- **demo1**: scoped-down app, built live by attendees with Genie app builder from a PRP, using the apx stack (FastAPI + React + TypeScript). Everyone starts from identical data created by a one-command script.
- **demo2**: full-scope reference app, deployed with a Databricks Asset Bundle (DAB).

## Platform story (shared architecture)

| Layer | Role |
|---|---|
| SQL warehouse | Reads curated gold Delta tables: the analytical "what happened" (map layers) |
| Genie (Conversation API) | Ad-hoc "why" questions nobody pre-built a chart for |
| Lakebase | Stores what users create: reassignments, exceptions, approvals, comments, status. Low-latency reads/writes |
| Databricks Apps | The surface that ties them together and finishes the workflow |

Action -> insight loop: insight in (warehouse + Genie) -> action out (decision written to Lakebase) -> loop closes (Lakebase records synced back to the lakehouse as labeled data for the next model, report, or audit).

Why a dashboard cannot do this: no write-back, no per-user state, no workflow.

## Core Features

### demo1 (MVP, scoped down, apx, built with Genie app builder)

1. **Delivery map**: today's stops as points colored by status (on-time / at-risk / late), depot markers, route lines. Geospatial is mandatory.
2. **At-risk route list**: ranked routes with risk reason; click focuses the map.
3. **Reassign stop**: dispatcher moves a stop to another route/vehicle; written to Lakebase with a reason code.
4. **Exception log**: record exception (customer unavailable, weather, vehicle down) with reason and status.
5. **Ask Genie**: embedded chat via Conversation API for "why" questions.

### demo2 (full scope, DAB)

All of demo1 plus:

6. **Map layers**: stop clusters, route lines, depot catchments, historical on-time layer; toggles and filters (depot, carrier, region, date).
7. **Approval queue**: expedite-fee requests with approve/reject, approver identity, comment.
8. **Live route state**: per-route state (planned, in progress, delayed, completed) in Lakebase, reflected across users.
9. **Per-user state and audit trail**: every action attributed to the signed-in user (OBO); filterable audit log; comments on stops/routes.
10. **Closing the loop**: Lakebase decision tables synced back to Unity Catalog as labeled data (decision + reason); positioned as training signal for a routing model.
11. **Operational extras**: Genie space over gold tables; AI/BI manager dashboard; scheduled sync job; seed/reset job; roles/permissions.

## Data

| Source | Where it lives | Needs ingestion? |
|---|---|---|
| Synthetic gold Delta tables: depots, vehicles, carriers, routes, stops (lat/lon), deliveries/on-time history, SLA facts | Unity Catalog, created by demo1 setup script | Yes: generated by script, identical for every user |

| Labeled decisions (synced back) | Unity Catalog via synced/reverse sync | demo2 |

**Sensitivity:** synthetic data only; no real PII.

## Success Criteria (measurable)

- [ ] One script gives a new workspace user all gold tables and a Genie space in under 15 minutes.
- [ ] Attendee builds demo1 from the PRP in Genie app builder in under 45 minutes; map renders and a reassignment persists across reload.
- [ ] Dispatcher completes spot at-risk route -> reassign stop -> record reason in under 60 seconds.
- [ ] demo2 deploys with `databricks bundle deploy`; every action appears in the audit trail (user, time, reason) and in the synced UC labeled-data table.
- [ ] Genie answers the two canonical questions (depots missing SLA last week; late deliveries by carrier in the Northeast) correctly against seeded data.

## Non-Goals

- **Not** a routing/optimization engine: reassignment is manual.
- **Not** real-time telematics ingestion; route state is simulated/user-driven.
- **Not** multi-tenant, billing, or auth beyond Apps OBO/permissions.
- **Not** training the routing model in the workshop; only producing labeled data.
- **Not** customer-specific branding or data; brand-neutral and synthetic.
- **Not** a mobile or driver-facing app.
- demo1 **not** including approval queue, live state sync, or reverse sync (demo2 only).

## App Architecture

| Requirement | Component |
|---|---|
| Curated analytics reads | Databricks SQL warehouse over UC gold Delta |
| "Why" questions | Genie Conversation API |
| Writes, low-latency state | Lakebase (Postgres) |
| Map | Web map library (MapLibre/deck.gl), open tiles, no API key |
| Hosting | Databricks Apps; demo2 via DAB (app, Lakebase, jobs, Genie, dashboard) |
| Sync back | Lakebase -> UC synced tables + scheduled job |

4. Scale: ~8 depots, ~60 vehicles, ~25 routes/day, ~2,500 stops/day, 30 days history.
